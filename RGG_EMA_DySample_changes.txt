RGG compatibility with EMA and DySample
Date: 2026-10-13 (Asia/Manila)

Purpose
Ensure that the existing RGG backbone, Efficient Multi-Scale Attention (EMA)
blocks, and DySample neck work together during training, checkpoint loading,
weight averaging, and deployment. The enhanced architecture uses EMA after
the P3/P4/P5 RGG blocks and DySample in both top-down neck paths.

Finding
The existing feature dimensions were already compatible. RGGConv and
RGGBottleneck, however, registered the same internal modules under multiple
names. PyTorch serialized the same parameters and buffers repeatedly under
these aliases. Ultralytics ModelEMA iterates over every state_dict entry,
so it updated some shared tensors multiple times per optimizer step.

ModelEMA is the training engine's exponential moving average of weights.
It is separate from the Efficient Multi-Scale Attention module in the backbone.

Changes
1. paddy_yolo/modules/rgg.py
   - Added _CanonicalModuleAliases to keep one registered name per module.
   - Replaced RGGConv cv1/cv2/cv3/fuse module registrations with properties
     pointing to rep/ghost1/ghost2/conv.
   - Replaced RGGBottleneck rgg_conv registration with a property pointing
     to cv2.
   - Added historical whole-model checkpoint normalization in __setstate__.
   - Added legacy state_dict alias migration so old checkpoints can still
     load strictly. Canonical keys take precedence over duplicated alias keys.
   - Preserved the actual RGG feature computation and pretrained tensor names.

2. tests/test_rgg_ema_dysample.py
   - Added joint RGG -> EMA -> DySample forward and backward checks at
     64, 128, and 256 channels, with LP and PL sampling styles.
   - Exercised odd feature sizes and noncontiguous input tensors.
   - Checked finite gradients in RGG, EMA attention, and DySample offsets.
   - Checked CPU bfloat16 autocast.
   - Verified that weight averaging updates every floating state tensor once.
   - Checked historical state-only and whole-model checkpoint loading.
   - Checked equivalent output after RGG RepConv deployment fusion and
     parity between RGG forward and forward_split.

3. kaggle/ema_dysample/ema_dysample.ipynb
   - Rebuilt the notebook with the corrected RGG implementation and new tests.
   - The source archive contains 49 allowlisted files.
   - Checked that all code cells compile and that embedded RGG/test sources
     match the current repository files.

Model and pretraining verification
- Enhanced model parameter count: 3,388,416.
- State entries decreased from 1,471 to 625 after duplicate aliases were removed.
- Every state entry in the enhanced model has unique tensor storage.
- 283 compatible yolov8n.pt tensors still transfer, and every transferred
  tensor was compared exactly against its source checkpoint.
- Parameter coverage remains approximately 70.80%; new RGG paths, EMA,
  DySample, and incompatible classification tensors still initialize separately.
- The downloaded best.pt from the previous Kaggle run loads with the revised
  code and produces finite CPU predictions with shape [1, 20, 84] at 64x64 input.
- The historical best.pt file was not rewritten; its checksum is preserved.

Validation
- Focused RGG, EMA, and DySample suite: 38 passed.
- git diff --check: passed.
- Full repository suite: 111 passed in 227.55 seconds.
- Full-suite command: .venv/Scripts/python.exe -m pytest -q
  --basetemp=.local/pytest-rgg-compat-full

Limits
These changes fix duplicate state registration and verify module integration.
They do not establish the cause of the previous run's lower accuracy or prove
an accuracy improvement. GPU FP16 training must be checked in a subsequent
Kaggle run; the mixed-precision check in this change uses CPU bfloat16.
The existing training hyperparameters and archived evaluation scores describe
the previous run. No new Kaggle job was submitted as part of this code change.
